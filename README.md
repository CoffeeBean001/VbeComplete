# VbeComplete

给 VBA 编辑器（VBE）补上它原生不给的东西：**你自己写过的名字**（声明过的、没写 `Dim` 的隐式变量都算）。支持 Office / WPS 全家桶，按前台窗口自动识别宿主。不在 VBE 代码窗里时一个 COM 调用都不发，空闲时几乎零开销。

## 提示词怎么弹

只要光标前有词就弹，不看位置：注释、字符串、声明处、`As` / `New` 之后、`对象.` 之后一律照常给候选。`Ctrl+Space` 随时手动唤出。

唯一的过滤是**作用域**，三档互不泄露：

| 档 | 内容 | 可见范围 |
| --- | --- | --- |
| 4 过程级 | 本过程里出现或声明的名字、参数 | 仅本过程 |
| 3 模块级 | 模块级名字（含 `Private` 与隐式名字）、窗体控件 | 仅本模块 |
| 2 工程级 | 其它模块的 `Public` 声明 | 全工程 |

类 / 窗体 / 文档模块的 `Public` 成员是对象成员，只能通过 `c.x` 访问，不作为裸名字提示。排序依次看：命中档次 → 模糊匹配分 → 作用域档位 → 名字长度 → 字母序。

候选池只有一个来源：代码。声明过的、出现过的标识符都进池（`Sheet1.Range(...)`、`ListBox1.List` 里的名字也算）；工程里有但你没写过的模块名不会自己冒出来。已经打全的名字不再提示自己。

`Tab` 接受（整词替换，补完不再追加 `()` 或空格），`Enter` 永远是换行，空格或词尾符号关掉列表。

## 功能

- 托盘常驻，右键菜单：代码片段、开机自动启动、退出。自启写 `HKCU\...\Run`，不需要管理员权限；双击托盘图标直接开片段窗。
- 候选只来自你的代码 —— 作用域分析扫出来的变量名、过程名、类型名，以及代码里出现过的其它标识符（`Sheet1`、`ListBox1` 写过就提示，没写过就不提示）。VBA 关键字与内置函数不提示。
- 支持中文标识符，逐字符高亮匹配，自绘候选窗固定 10 行、字体字号与 VBE 编辑器一致。
- 回车自动缩进 + 补收尾（`End If` / `Next` / `End Sub`），自动配对括号（中文标点档换全角），`Ctrl+/` 注释切换。
- `Ctrl+Q` 片段库（`snippets-cs.db`）。

## 构建与运行

需要 **.NET 10 桌面运行时**（仅 Windows）。宿主那边自己勾选「信任对 VBA 工程对象模型的访问」—— 程序不碰这个开关，也不写注册表。

```
build.bat                    编译并发布单文件到 dist\VbeComplete.exe
run-cs.bat                   启动（没有主窗口，看托盘图标）
stop-cs.bat                  结束进程
```

## 每键开销

解析是**增量**的。后端维护一份整模块的行镜像，改一行就只改那一行，再把这一行的结构事件 / 声明 / 自由标识符增量喂给作用域模型。**不会为一次按键重读全文，也不会重析全模块。**

候选池拆成两段：**头**是本过程能直接用的名字（几十项，每键重算），**尾**是本模块的名字加别的模块导出的名字（按模块级版本号缓存，只有改到过程外或别的模块时才重建）。匹配前先用 64 位字符掩码挡掉"名字里根本没这些字符"的项，再走子序列判定，绝大多数名字连字符串都不碰。

实测（i5-12600KF，离线基准，假后端，单线程，多轮平均）：

| | 5,000 行 | 50,000 行 | 100,000 行 |
| --- | --- | --- | --- |
| 一次按键（改一行 + 取候选） | 1.6 µs | 3.7 µs | 7.7 µs |
| 　其中：本过程名字重算 | 0.4 µs | 1.6 µs | 3.2 µs |
| 回车（插入一行） | 1.0 µs | 7.5 µs | 15 µs |
| 结构化改动（插 Sub 头 + End Sub） | 0.04 ms | 0.5 ms | 1.0 ms |
| 整模块首次解析（打开模块 / 粘贴整段） | 5 ms | 84 ms | 173 ms |

2,000 行的模块一次按键约 1 µs。池子尾段重建（改到过程外的代码）才有一点可见成本：5,000 行 6 µs、50,000 行 31 µs、100,000 行 54 µs。10 万行模块的整份镜像 + 逐行事件约 30 MB。

正确性靠离线基准守着：增量结果与"整模块全量重析"在 300 次随机编辑（改行 / 插行 / 删行 / 粘贴）后逐行一致，候选集合与"逐名暴力枚举"在 400 次随机查询下完全一致。

宿主侧的开销几乎全在**跨进程 COM** 和**自绘弹窗**上，解析只占百分之几。这两块各自按"单次调用"实测过，下表的合计是分项之和：

| 环节 | 耗时 | 说明 |
| --- | --- | --- |
| 焦点判定（纯 Win32） | 0.002 ms | 不碰 COM |
| `ActiveCodePane` | 0.07 ms | 每次快照一次 |
| `GetSelection` | 0.054 ms | 缓存了 dispId、复用参数缓冲（原先 0.109） |
| `CodeModule` + `Name` + `Lines` | 0.20 ms | 打字时每快照一次 |
| 候选匹配 `Trigger` | 0.003 ~ 0.06 ms | 见上表，与模块规模有关 |
| 候选窗一帧 `OnPaint`（10 行） | 0.41 ms | 整帧共用一次 HDC + 直接 `TextOutW`（原先 1.77） |
| **合计：按键 → 候选窗可见** | **约 1.1 ~ 1.4 ms** | 一次按键通常触发两次快照 |

两处结构性改动值得记一笔：

- **弹窗自绘**：`TextRenderer` 每调一次都会 `GetHdc/ReleaseHdc` 一次，10 行文本就是几十次，单帧 1.77 ms 里绝大部分花在这个来回上。改成整帧共用一次 HDC、直接 `TextOutW`，并把字体宽度按"等宽乘法 / `GetTextExtentPoint32W`"算出来，一帧 0.41 ms。输出与原来**逐像素一致**（同一段文本用两种方式各画一遍，70400 个像素零差异；等宽 / 比例 / 中文三种字体下宽度也逐一核对过）。
- **COM 调用**：`GetSelection` 的 dispId 缓存起来、参数缓冲只分配一次，单次调用从 0.109 ms 降到 0.054 ms；同一张快照能复用时跳过 `CodeModule` + `Name`（靠 CodePane 对象身份判断有没有换模块）。

闲置时的开销：VBE 没在前台时一次 COM 都不发（实测 0.1% 单核，全是那一下 Win32 焦点判定）；VBE 在前台但没在打字时，轮询间隔从 150 ms 放宽到 400 ms（WPS 300 → 600），并且跳过"再读一次选区"的自洽复核，约 0.03% 单核。

常驻内存约 71 MB 工作集 / 25 MB 私有（.NET 运行时占大头，10 万行模块的镜像再加 30 MB）。

不在宿主进程前台时（例如切到浏览器），焦点判定直接判否，一次 COM 都不发。

## 片段库

只有一个库文件 `snippets-cs.db`，一张两列表 `snippets`（`title` 主键 + `code`）。用 `Ctrl+Q` 或托盘菜单打开，增删改都在窗口里，改完立刻可用。

## 目录

```
src/*.cs              源码；rules / scope / engine 三层不引用 UI
dist/VbeComplete.exe  build.bat 的产物
settings.ini          配置（全部注释掉 = 全用默认值）
snippets-cs.db        片段库
```

## 已知限制

- 不在代码窗里（或 VBE 没拿到焦点）时不工作，切回 VBE 有短暂延迟。
- 全工程作用域默认每 2 秒重扫一次（`SCOPE_TTL`），模块极多时第一次补全有几十毫秒延迟。
- 补全行为没有开关可调，想改只能改代码。VBA 关键字与内置函数**有意不提示**，不是漏了。
- `settings.ini` 只剩排障 / 换路径 / 性能几项，改完重启生效。
